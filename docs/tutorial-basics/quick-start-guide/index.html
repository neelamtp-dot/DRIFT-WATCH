Driftwatch Quick Start Guide

Time to complete: about 10 mins Auidence: Devops Engineers and Platform Engineers Applies to: Driftwatch CLI v2.4 and later

What is Driftwatch?​

Driftwatch is a command-line tool that compares the live state of your cloud infrastructure against your Terraform definitions and reports any differences. These differences are called drift. Drift happens when someone changes a resource manually in the cloud console, or when another tool modifies it outside your normal deployment process.

In this guide, you will:

  1. Install the Driftwatch CLI.
  2. Connect it to your clound account.
  3. Run your first drift scan.
  4. Read the scan report.

Before you Begin​

Make Sure you have following:

RequirementDetails
Operating SystemmacOS 12+, Ubuntu 20.4, or Windows 10+ (with WLS2)
TerraformVersion 1.5 or later, with an existing project
Cloud accountAn AWS account with read-only access
Driftwatch accountSign up for free to get an API key
note

Driftwatch only needs read-only permissions. It never changes your infrastructure.

Step 1: Install the CLI​

Choose the method of operating system. macOS (Homebrew)

brew install driftwatch/tap/driftwatch

Linux (script)

curl -fsSL https://example.com/install.sh | sh

Windows (WSL2)

Open your WSL2 terminal and run the Linux command above.

Verify the installation:

driftwatch --version

Expected output:

driftwatch version 2.4.1

Step 2: Authenticate​

  1. Sign in to the Driftwatch dashboard.

  2. Go to Settings > API Keys and select Create key.

  3. Copy the key. It is shown only once.

  4. Run the login command and paste your key when prompted:

    driftwatch login

    Expected output:

    ✔ Authenticated as jane@example.com
warning

Never commit your API key to version control. For CI pipelines, store it in the DRIFTWATCH_API_KEY environment variable instead.

Step 3: Connect your cloud account​

Driftwatch uses your existing AWS credentials. Run:

driftwatch connect aws --profile default

If you use a named profile, replace default with your profile name.

Step 4: Run your first scan​

Go to your Terraform project directory and run:

cd ~/projects/my-infrastructure
driftwatch scan

Driftwatch reads your Terraform state, queries the live resources, and compares them. A typical scan takes 30 to 90 seconds.

Step 5: Read the report​

When the scan finishes, you will see a summary like this:

Scan complete: 42 resources checked

  ✔ 39 in sync
  ⚠ 2 drifted
  ✖ 1 missing

Drifted resources:
  aws_security_group.web
    ~ ingress.0.cidr_blocks: ["10.0.0.0/16"] → ["0.0.0.0/0"]

  aws_s3_bucket.logs
    ~ versioning.enabled: true → false

Understanding the symbols​

SymbolStatusMeaning
✔In syncLive resource matches your Terraform code
⚠DriftedLive resource differs from your Terraform code
✖MissingResource exists in Terraform but not in the cloud

In the example above, someone opened the web security group to the whole internet (0.0.0.0/0) and disabled versioning on the logs bucket. Both changes were made outside Terraform.

Troubleshooting​

ProblemCauseSolution
command not found: driftwatchCLI is not on your PATHRestart your terminal, or add the install directory to your PATH
Error 401: invalid API keyKey was copied incorrectly or revokedCreate a new key and run driftwatch login again
Error: no Terraform state foundYou are not in a Terraform project folderRun the scan from the directory that contains your .tf files
Scan takes more than 5 minutesLarge account or slow networkLimit the scan with driftwatch scan --target aws_s3_bucket

Still stuck? Contact support@example.com and include the output of driftwatch --version and driftwatch scan --debug.
