CLI Command Reference

This page describes every Driftwatch CLI command, with its syntax, options, and examples.

Applies to: Driftwatch CLI v2.4 and later

Command syntax​

driftwatch <command> [subcommand] [arguments] [options]

In this Reference:

  • <value> is a required value.
  • [value] is optional.
  • a | b means choese one.

Commands at a glance:​

CommandDescription
loginAuthenticate with your Driftwatch account
logoutRemove Stored Credentials
connectConnect a cloud account
scanScan for infrastructure drift
ignoreManage rules for expected drift
scheduleRun scans automatically
notifyConfigure drift alerts
doctorDiagnose your installation

Global options​

These options work with every command.

OptionDescriptionDefault
-h, --helpShow help for a command
--versionPrint the CLI version and exit
--config <path>Use a specific configuration file~/.config/driftwatch/config.yaml
--debugPrint detailed diagnostic outputfalse
--no-colorTurn off colored outputfalse
-q, --quietPrint errors onlyfalse

driftwatch login​

Authenticate the CLI with your Driftwatch account.

Syntax​

driftwatch login [options]

Options​

OptionDescriptionDefault
--api-key <key>Provide the API key without a prompt
--stdinRead the API key from standard inputfalse

Examples​

Sign in interactively:

driftwatch login

Sign in from a script, without exposing the key in your shell history:

echo "$DRIFTWATCH_API_KEY" | driftwatch login --stdin
tip

In CI pipelines, skip login and set the DRIFTWATCH_API_KEY environment variable instead.

driftwatch logout​

Remove stored credentials from your machine. This does not revoke the key. To revoke it, go to Settings > API Keys in the dashboard.

Syntax​

driftwatch logout

driftwatch connect​

Connect Driftwatch to a cloud account so it can read live resources.

Syntax​

driftwatch connect <provider> [options]

Arguments​

ArgumentDescription
providerCloud provider. Supported value: aws

Options​

OptionDescriptionDefault
--profile <name>AWS profile to usedefault
--region <region>AWS region to scanRegion from the profile
--role-arn <arn>IAM role to assume for read-only access

Examples​

Connect with the default profile:

driftwatch connect aws

Connect with a named profile and a specific region:

driftwatch connect aws --profile production --region eu-west-1

driftwatch scan​

Compare live infrastructure with your Terraform definitions and report drift. Run this command from the directory that contains your Terraform files.

Syntax​

driftwatch scan [options]

Options​

OptionDescriptionDefault
--target <type>Scan only this resource type. Repeat the option for multiple typesAll types
--dir <path>Terraform project directoryCurrent directory
--output <format>Output format: text, json, or sariftext
--out-file <path>Write the report to a file instead of the terminal
--fail-on-driftExit with code 2 if drift is foundfalse
--timeout <duration>Maximum scan time, for example 10m15m
--format <format>Deprecated. Use --output

Examples​

Scan everything in the current project:

driftwatch scan

Scan only S3 buckets and security groups:

driftwatch scan --target aws_s3_bucket --target aws_security_group

Save a JSON report and fail a CI job if drift is found:

driftwatch scan --output json --out-file report.json --fail-on-drift

Output​

Scan complete: 42 resources checked

  ✔ 39 in sync
  ⚠ 2 drifted
  ✖ 1 missing

For a description of each symbol, see Read the report.

driftwatch ignore​

Create and manage rules that hide expected drift from scan reports. Rules are saved in .driftwatch/ignore.yaml in your project directory.

Syntax​

driftwatch ignore add <resource> [options]
driftwatch ignore list
driftwatch ignore remove <resource>

Subcommands​

SubcommandDescription
addAdd an ignore rule
listShow all ignore rules
removeDelete an ignore rule

Options for add​

OptionDescriptionDefault
--attribute <path>Ignore only this attribute, for example tags.updated_atWhole resource
--reason <text>Explain why the drift is expected
--expires <date>Remove the rule automatically on this date (YYYY-MM-DD)Never

Examples​

Ignore a tag that another tool updates automatically:

driftwatch ignore add aws_instance.web \
  --attribute tags.last_patched \
  --reason "Updated by patch management tool"
note

Always add a --reason. It helps your team understand the rule later.

driftwatch schedule​

Run scans automatically on a recurring schedule.

Syntax​

driftwatch schedule create [options]
driftwatch schedule list
driftwatch schedule delete <schedule-id>

Options for create​

OptionDescriptionDefault
--cron <expression>Schedule in cron format, for example "0 6 * * *"Required
--dir <path>Terraform project directoryCurrent directory
--name <name>Friendly name for the schedule

Example​

Run a scan every day at 06:00 UTC:

driftwatch schedule create --cron "0 6 * * *" --name "daily-prod-scan"

driftwatch notify​

Send drift alerts to a messaging tool.

Syntax​

driftwatch notify slack --webhook-url <url> [options]

Options​

OptionDescriptionDefault
--webhook-url <url>Slack incoming webhook URLRequired
--channel <name>Channel to post toWebhook default
--min-severity <level>Alert only at or above this level: low, medium, highmedium

Example​

driftwatch notify slack \
  --webhook-url "$SLACK_WEBHOOK_URL" \
  --min-severity high

driftwatch doctor​

Check that Driftwatch is installed correctly and can reach the services it needs.

Syntax​

driftwatch doctor [options]

Options​

OptionDescriptionDefault
--verboseShow detailed results for each checkfalse

Output​

✔ Driftwatch CLI 2.4.1
✔ Terraform 1.7.0 found
✔ Network: api.driftwatch.example.com reachable
⚠ Not authenticated. Run "driftwatch login".

Environment variables​

Environment variables override values in the configuration file.

VariableDescription
DRIFTWATCH_API_KEYAPI key. Use this in CI instead of driftwatch login
DRIFTWATCH_CONFIGPath to the configuration file
DRIFTWATCH_CA_BUNDLEPath to a custom CA certificate bundle
DRIFTWATCH_NO_COLORSet to 1 to turn off colored output
HTTPS_PROXYProxy server for outgoing connections
NO_PROXYHosts that should bypass the proxy

Exit codes​

Use exit codes to control CI pipelines and scripts.

CodeMeaning
0Success. No drift found, or --fail-on-drift was not set
1General error, such as invalid options or a network failure
2Drift detected (only with --fail-on-drift)
3Authentication failed
4Terraform state not found or unreadable
